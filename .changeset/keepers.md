Keepers review every commit before you do. Open a task on a branch — in its own worktree or in your project folder — choose the new **Keepers** tab at the end of the rail and pick **Add keeper** — Review for bugs and edge cases, Slop for code that reads as generated, or Conventions for your project's written rules. Each keeper checks what the agent commits and hands its findings back to the same agent as one fix request, shown in the chat as **Keepers asked for a fix**. The tab shows every keeper's last ten runs at a glance, lists open findings with a link to the exact line, and lets you **Dismiss** the ones that are wrong so they are not raised again. When fixes stall, the keeper stops and asks you to extend, accept the change as it is, or switch it off for the task. The Keepers button and the task's row in the sidebar turn red when a keeper needs you, and switching a keeper off for one task leaves the rest untouched. In the project folder, keepers follow the task that last worked on the checked-out branch and pause while you are on another branch. Pushing or opening a pull request while a keeper still has findings shows which keepers are not green, so you push knowingly. Once a task has a pull request, its icon in the sidebar, the task header and Mission Control carries a red dot while a keeper has findings or needs you, and a keeper that needs you puts the task in your **Needs you** queue. Five more keepers run when the work is done rather than on every commit — Security, Thermonuclear, Intent, Verify and PR-ready, under **Before the pull request** in **Add keeper**. Press **Check before PR** in the Keepers tab, or open **Create PR**, and they check the branch's latest commit; the pull request form lists each one as it finishes, and PR-ready's description fills the form when you have not written one yourself. None of them ever stops you from opening the pull request. When findings were left behind on an older commit, **Send to agent** on the keeper's card hands them to the task's agent yourself, and the agent checks each one still holds before fixing it. When the agent pushes back on a finding instead of fixing it, its reason shows under the finding and **Accept** dismisses it in one click — no retyping why.
